# Theoretical contention model and measured fixture

Date: 2026-10-12. This note separates analytical estimates from FlowSim measurements.

## Workload-derived quantities

Model: `Qwen/Qwen3-30B-A3B-Instruct-2507`, BF16, 48 layers, 4 KV heads,
`head_dim=128`, TP1. The model-derived KV volume is

```text
48 layers × 2(K,V) × 4 KV heads × 128 × 2 B = 98,304 B/token
2048-token request = 201,326,592 B (192 MiB); each layer = 4 MiB
1024-token request = 100,663,296 B (96 MiB); each layer = 2 MiB
```

Each server is represented as 8 GPU ranks with 2 independent 200-Gbps
scale-out NIC rails, four GPUs per rail. Each NIC-facing directed link is
200 Gbps (25 GB/s); TX and RX are separate resources. GPU-to-NIC access is
modeled with a high-capacity 7.2-Tbps edge. This is a FlowSim abstraction of
GPU/NIC access, not a measured PCIe/NVLink path.

Profile-backed layer-release intervals are 1.537064 ms for 2048 input tokens
and 1.190772 ms for 1024 input tokens. These differ slightly from the
1.542-ms planning estimate; the integrated runs use the emitted profile trace.
The resulting average P2D demands are 21.830 and 14.089 Gbps/request. One
recurrent EP4 seed group contributes an estimated 1.405 Gbps on its receiving
rail. Thus the primary rail-local mixture is approximately
`7×21.830 + 2×14.089 + 1.405 = 182.396 Gbps`, or 91.20% of one 200-Gbps
direction. The 8-long-request neighbor is 88.02%. These are average
model/profile-derived offered-load estimates, not utilization measurements.

## EP traffic derivation and theoretical ceiling

The tested collective realization is the simulator's model-derived
ALLGATHER dispatch plus REDUCESCATTER combine expanded to 12 peer flows per
EP4 group round. It is not GateRouter exact A2A. At the tested batch shape,
dispatch is 4×4,352 B and combine is 4×1,024 B per receiving rail per layer;
across 48 layers this is 1,032,192 B/token/rail. At the measured 5.875528-ms
seed TBT the average is about 1.405 Gbps.

For nine same-cut KV flows and four cross-server critical EP peer messages,
a simple serialization-only max-min comparison predicts roughly 1.57 us
dispatch plus 0.37 us combine difference per MoE layer. If all 48 layer
differences were serial and fully exposed, the ceiling would be about 93 us
per token, approximately 1.58% of 5.875528 ms. This is an intentionally
generous bound: the simulator overlaps compute and communication, and not
every peer message is on the collective critical path. It predicts that
EP-vs-KV can be measurable in collective latency while the maximum serving
effect remains small.

## Physical topology and actual integrated fixture

The candidate requests and two independent EP4 groups share the same
receiver-side D0 NIC rails. For direction A, one rail is exercised at a
time. For direction B, both D0 rails are exercised independently. The
generated physical topology contains 4 Prefill servers and 2 Decode servers,
each with 8 GPU endpoints and 2×200G NIC rails, connected to one ToR. The
serving config has multiple logical Decode nodes/instances mapped to those
physical GPU ranks; it is not an 8-Decode-server topology. Rank-to-physical
mapping is in `generated/logical_to_physical.json`.

This is a controlled mechanism workload, not a natural trace. Candidate
arrival was selected from simulator events: all seed Decode groups were
admitted and had completed at least four Decode iterations. The observed
event time was 67,284,113 ns. Candidate arrival alignment is intentionally
favorable to overlap, and results must not be generalized to production
frequency.

For the measured B run, the candidate KV work window is first KV release
67.431113 ms through last candidate `p2d_kv_ready_time` 141.752113 ms
(74.321 ms). The telemetry writer emits rows only while a link has active
flows; gaps reconstruct as no allocated flow. On each D0 RX rail, active
full-capacity intervals total 64.872308 ms, giving a measured time-weighted
occupancy of 87.29% during this window. There are 207 event-driven busy
episodes, the longest 1.522 ms: high average demand is generated by repeated
layer bursts, not one uninterrupted saturation episode. Under FAIR,
simultaneous KV+EP-active intervals total 1.296263 ms (1.74% of this window)
per rail. Same-window overlap is 0.462562 ms (0.62%) under EP_FIRST and
62.624769 ms (84.26%) under KV_FIRST, where EP flows remain active/pending
behind strict KV-class service. These are FlowSim event-derived fluid
intervals, not packet queue occupancy.

## Limits of the analytical model

FlowSim uses directed-link max-min fluid allocation. Its residual backlog is
analytical fluid work, not packet-buffer occupancy. The estimate does not
model packet serialization, RNIC/QP dequeue scheduling, ECN/CNP, PFC, packet
HOL, or DCQCN. For measured findings and interpretation, see
`02_DIRECTION_A_RESULTS.csv`, `03_DIRECTION_B_RESULTS.csv`, and
`05_NIC_VS_FABRIC_ATTRIBUTION.md`.
