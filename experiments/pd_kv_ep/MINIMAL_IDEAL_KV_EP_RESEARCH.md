# Minimal Ideal KV–EP Gate

Status: **`MINIMAL_IDEAL_KV_EP_FINAL_FAIL`**. D16K8 completed at the most
favorable prescribed population with verified P2D/EP overlap on shared
200-Gbps ToR ingress, but EP CCT P99 slowdown is +5.11%, KV residual-drain
P99 is +3.66%, and integrated TBT P99 changes by +0.47%. Both network barrier
metrics are below the 10% stop gate; stop this research line. See
[`MINIMAL_IDEAL_KV_EP_FINAL_FAIL.md`](MINIMAL_IDEAL_KV_EP_FINAL_FAIL.md).

## Gate question

In a minimal, legal 1P2D PD-MoE cluster, do concurrent layerwise P2D KV and
Decode EP16 share the modeled data-plane resources, and does the resulting
queue/service interference reach either the EP collective completion barrier
or the request-level KV handoff barrier?

This is a controlled mechanism gate, not a production-arrival claim. It uses
Qwen3-30B-A3B-Instruct-2507, model-derived bytes and exact GateRouter peer
routing. No scheduler, routing, or priority design is implemented in this
phase.

## Correctness and physical-resource gate

See [`MINIMAL_1P2D_TOPOLOGY_AUDIT.md`](MINIMAL_1P2D_TOPOLOGY_AUDIT.md).
The generator, cluster configuration, rank-to-NIC map, pairing map, and
single-ToR topology are under `configs/large_scale/`.

Passed checks (topology/unit checks only):

- ACTUAL receiver-mode cluster build: 24 ranks; P0 ranks 0–7, D0 ranks 8–15,
  D1 ranks 16–23; EP16 global ledger ranks 8–23; ASTRA dimensions `[2,12]`.
- Model-derived Qwen layer KV at 8192 prompt tokens: 16,777,216 B per layer;
  one TP1 source rank maps to two 8,388,608-B TP2 destination shards.
- A P0→D0 P2D route and a D1→D0 EP route share the directed ToR→D0-NIC0
  200-Gbps link. Both also use the D0-NIC0→D0-GPU0 local endpoint attachment.
- FlowSim max-min unit probe verified that concurrent flows share that
  200-Gbps cut. This is only a topology unit test: it is not an EP workload or
  evidence that a real collective barrier slows down.
- Native ns-3 topology parser creates bidirectional directed link resources
  from each physical topology row. FlowSim queue telemetry remains
  analytical/fluid backlog.

## Configuration constraints

- Physical servers: P0, D0, D1; eight GPUs per server.
- Server NICs: two independent 200-Gbps scale-out NICs/server; four GPUs share
  each NIC via fast local fabric. Per-GPU 50-Gbps is arithmetic only.
- One ToR, no spine. No intentional oversubscription or path pinning.
- Qwen3: 48 layers, 128 experts, top-k 8. Prefill uses eight TP1 instances;
  Decode uses eight TP2 instances, four per Decode server, as the available
  supported TP profiles do not provide a legal TP8 profile. The Decode DP
  group is EP16 with local EP2 per TP2 instance.
- `LAYERWISE` is primary; `POST_PREFILL` is a granularity control only.
- Cross-server EP is only D0↔D1 traffic. Intra-server EP remains on local
  fabric and must not be counted as scale-out load.
- First comparison is `EP_ONLY`, `KV_ONLY`, `FULL_FAIR`. Priority policies
  are deferred until natural FAIR barrier exposure is established.

## Workload / search procedure

Two controlled cohorts are required. Cohort D first enters through legal P/D
serving, completes P2D, is admitted to Decode, and completes at least four
Decode iterations. Only then is cohort K injected. The injection point must be
derived from the completed D-only event ledger, and the same request prefix
must be verified in the mixed run. Do not use an arbitrary fixed timestamp.

Starting D/K points are D2K1, D4K1, D8K1, D8K2, D8K4, D16K4, D16K8. D requests
use 128 input / 128 output tokens. K requests use 8192 input / 2 output tokens.
Two output tokens are the smallest legal completed P/D request in this
simulator: Prefill emits the first token, and one Decode token is required to
retire the request and produce a serving CSV row. A 1-token K request transfers
KV but is handed to Decode with no remaining work and never retires; that
attempt is retained as a correctness diagnostic, not treated as a result.
Every request remains a normal serving request; all P2D and EP bytes are
generated by model/routing semantics. Run the smallest points first and branch
only on the observed state (`NO_OVERLAP`, `OVERLAP_NO_QUEUE`, `TRANSIENT_QUEUE`,
`PERSISTENT_QUEUE`, `EP_BARRIER_EXPOSED`, `KV_BARRIER_EXPOSED`). Change one
population dimension at a time.

At each point, derive the measurement interval end from the earliest K Decode
admission in FULL. This keeps the EP comparison on the active-D population
while excluding K's own Decode collective, so the measured change isolates
cross-request P2D overlap. Match D-only EP CCT and TBT over the same interval.

At each point, collect integrated FlowSim scheduler/request metrics and compact
network telemetry. Required network metrics: EP CCT mean/P50/P95/P99; KV request
handoff and `ResidualDrain = last required shard completion - last layer
release`; queue/backlog episodes and persistence versus EP period; shared-link
utilization; critical last peer and last KV shard attribution. Report TTFT,
TPOT, TBT/ITL only from a completed integrated serving output. Do not infer
them from a network-only replay.

## Stop rules

- Natural FAIR EP CCT P99 or KV residual-drain P99 slowdown ≥20%: stop scaling
  that axis and test one adjacent point for reproduction, then attribute the
  barrier.
- If contention appears but barrier metrics remain below threshold, inspect
  last-peer/last-shard slack before changing load.
- At the favorable legal D16K8 point, if both EP CCT P99 and KV residual-drain
  P99 slowdowns versus matched isolated baselines remain <10%, classify
  `MINIMAL_IDEAL_KV_EP_FINAL_FAIL`; stop this research line. Do not lower link
  rate, shrink buffers, alter model bytes, or search real traces for a lucky
  collision.
- If one barrier passes, validate a neighboring operating point. Only after
  natural FAIR exposure may FAIR/EP_FIRST/KV_FIRST be compared.
- Run native ns-3 only for bounded representative points after FlowSim/integrated
  results identify a natural mechanism. Packet-level queue/ECN/PFC evidence
  must not be conflated with FlowSim fluid backlog.

## D2K1 diagnostic (not a contention PASS)

The first matched integrated point used D=2 and K=1. Decode requests used 128
input / 128 output tokens and ran to completion before the 8192-token K request
was injected. The injection time was derived from the D-only request ledger:
66.034225 ms, after both requests were admitted and crossed four Decode token
boundaries. K used `output_toks=2`, the smallest setting that lets the
simulator retire it after one real Decode token.

The model-derived K payload was 805,306,368 B across 48 layers and 384
P2D shard/chunk transfers. Its first KV issue was 66.181225 ms; the last layer
was released at 432.071225 ms and the last required transfer completed at
432.249198 ms. Request-level network handoff span (first issue to last
completion) was 366.067973 ms; `ResidualDrain` after the last layer release
was 177.973 us. The long handoff span is predominantly the layer-release
timeline, not the sum of shard FCTs.

Within the event-derived measurement window, 66.034225–434.658225 ms, the
correctly filtered ledger contains 6,362 EP collectives in both D-only and
FULL. EP CCT mean/P50/P95/P99 were 17.2665/17.2665/23.022/23.022 us in both
runs (mean and P99 slowdown 1.000). D-cohort TBT P99 was 5.563056 ms in both
runs. K-only and FULL had the same P2D-ready time and 177.973-us residual
drain. FULL K TTFT was 378.297807 ms versus 371.129936 ms in K-only (+1.93%),
but this is not evidence of network interference: K was ready at the same
time; FULL added 4.101 ms of Decode-admission wait, and its first-token
iteration took 5.573 ms versus 2.506 ms in isolation. The TTFT delta is on the
Decode scheduler/compute side and must not be attributed to the fabric.

The timed EP/KV activity overlap was 10.003 ms. Captured common paths were
only `27->12` and `27->13`, the 7.2-Tbps local NIC-to-GPU attachments; no
shared ToR uplink was observed in the captured subset. The captured P2D
receiver was D0 NIC1, while the active D cohort used D0 ranks 8–11 on NIC0.
Therefore D2K1 did not establish the target 200-Gbps shared-uplink contention.

The first run has explicit telemetry limits: link samples reached their old
32,768-row cap at 99.787 ms, before the 434.658-ms measurement end; EP peer-flow
details reached their old 30,000-row cap at 155.206 ms. The summary marks the
fluid-link window incomplete. Absence of a later shared-path observation is
not treated as proof that no later overlap occurred. A2A_P2P collective rows
also omit `request_ids` in this code path, so cohort identity is bounded by
the serving-derived interval ending at the first K Decode admission, before K
can enter EP.

The first isolated K attempt exposed a genuine completion-gate bug:
`--num-reqs=0` means “load all” to the CLI, but the completion gate treated zero
as the expected number completed and could exit before P2D handoff.
`Router.load_requests()` now returns the actual expanded request count and the
main loop uses it; the experiment runner also passes the explicit JSONL count.
A one-token K request transfers KV but has no Decode work to retire, so the
minimum completed request uses two output tokens. These are simulator
correctness fixes, not delays or traffic overrides.

## D4K1: shared scale-out overlap, weak barrier exposure

Under fixed RR request routing and one-to-one pairing, K naturally targets D1
while the active D cohort occupies D0. The event-derived injection occurred at
67.186225 ms. The FULL run completed with 4 D requests and 1 K request, and the
matched EP-only measurement ended at the first K Decode admission (435.810225
ms), excluding K's own Decode EP.

The K transfer remained the same model-derived 805,306,368 B. D-cohort EP
traffic was 743,178,240 B in FULL. The captured P2D and EP peer paths overlap
on the directed ToR ingress `30->28` (D1 NIC0): 1,344 captured EP round/flow
pairs, with 9.856406 ms of request-level KV/EP active-window overlap. Thus
unlike D2K1, this point verifies the intended shared scale-out resource.

Barrier results are small:

| Metric | Isolated | FULL_FAIR | Relative change |
|---|---:|---:|---:|
| EP CCT mean | 17.2665 us | 17.2951 us | +0.17% |
| EP CCT P99 | 23.022 us | 23.350 us | +1.42% |
| KV residual drain P99 | 177.973 us | 180.595 us | +1.47% |
| D-cohort TBT P99 | 5.851056 ms | 5.853352 ms | +0.04% |
| K TTFT | 371.129936 ms | 375.034204 ms | +1.05% |

The FULL K TTFT delta is not interpreted as a pure fabric effect: the request
CSV attributes the difference primarily to Decode admission/first-token
serving time, while KV-ready timing is nearly unchanged. Integrated request
metrics are reported as observed, not causally assigned without that
decomposition.

FlowSim's analytical residual fluid backlog peaked at 4,218,772 B, including
on `30->28`; the measured P95 positive-queue episode was 1.301 us and its
duration divided by median EP period was 0.000222. Utilization reports peak at
the modeled capacity during event intervals, but the queue episode is much
shorter than an EP period. This is transient fluid backlog, not a packet
buffer. It does not expose a material collective/handoff barrier in this
point.

The full collective CCT/request ledgers cover the serving comparison. The
per-peer EP-path ledger in this run hit its 120,000-row cap at 250.024309 ms,
before the measurement end, so the count of overlapping peer paths is a
captured lower bound, not a complete whole-window path distribution. The
directed shared link is positively verified from captured rows, but detailed
last-peer attribution across the full window is incomplete. To keep the next
run's path attribution complete without retaining all local EP peers, the
runner now records only EP peer flows traversing directed ToR uplinks, with a
250,000-row cap. Collective CCT telemetry remains unfiltered and complete.

### D4 diagnosis and next point

The mechanism is present at the intended resource, but four active Decode
requests and one 8192-token P2D request produce only transient fluid backlog
and <2% barrier slowdown. The next information-bearing step is D8K1: increase
only active Decode population, retain one identical model-derived K request,
and use the event-derived injection rule. This tests whether higher recurrent
EP offered load turns the observed shared-uplink overlap into persistent
queueing. Do not add K requests unless D8's diagnosis shows the KV side is the
limiting pressure.

### D8 diagnosis and next point

Doubling D from four to eight increases aggregate model-derived EP bytes from
743,178,240 B to 1,486,356,480 B, while the same single K request remains
805,306,368 B. The shared directed cut and active overlap are verified, but
queue episodes remain far shorter than an EP period and both request barriers
move by only a few percent. This is not a reason to keep increasing Decode
alone: the next planned point D8K2 holds D fixed and increases concurrent
model-derived P2D population from one to two, testing the outstanding-KV
pressure dimension once. If that still produces only short-lived fluid queue
and <10% barrier changes, continue only through the predetermined bounded
points needed to reach the favorable D16K8 stop gate.

## Final stop gate: D16K8 — FINAL FAIL

D16K8 completed with sixteen active Decode requests and eight simultaneous
8192-token P2D requests. Total model-derived P2D KV was 6,442,450,944 B;
Decode EP traffic in the comparison window was 2,788,884,480 B. Event-derived
K injection was 70.607649 ms; the first K Decode admission ended the matched
comparison at 439.231649 ms. EP scale-out path telemetry extends beyond that
window and verifies 134,480 P2D/EP peer-round overlaps on shared ToR links.

Against the matched isolated runs:

- EP CCT mean: 19.2319→19.5846 us (+1.83%); P99: 25.644→26.954 us (+5.11%).
- KV residual-drain P99: 681.289→706.196 us (+3.66%). Arrival-to-KV-ready
  remains 368.624 ms in both runs.
- D-cohort TBT P99: 6.214912→6.244387 ms (+0.47%); TPOT P99:
  6.165975→6.180598 ms (+0.24%).
- K TTFT: 374.955056→380.966689 ms (+1.60%), but KV-ready did not move. The
  request ledger shows a 5.599-ms Decode-admission wait and a longer first
  Decode iteration; this is not attributed to a delayed P2D network barrier.
- Maximum residual fluid backlog is 16,775,791 B overall and 8,445,132 B on
  Decode ingress. P95 queue-positive episode is 3.258 us versus a 6,236.527-us
  median EP period (ratio 0.000522); no persistent multi-round queue appears.

The user-defined final gate is met: in the favorable D16K8 legal case, both
EP CCT P99 and KV residual-drain P99 slowdowns remain below 10%. Therefore
the current FlowSim shared-fabric KV×EP barrier-contention hypothesis is
`MINIMAL_IDEAL_KV_EP_FINAL_FAIL`. Do not run more D/K points, priority
policies, POST_PREFILL sensitivity, real traces, reduced link rates, packet
replays, or larger topologies to search for a positive case. Full details and
all point metrics are in
[`MINIMAL_IDEAL_KV_EP_FINAL_FAIL.md`](MINIMAL_IDEAL_KV_EP_FINAL_FAIL.md).
