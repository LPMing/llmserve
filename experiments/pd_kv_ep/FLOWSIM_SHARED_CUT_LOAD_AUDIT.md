# FlowSim shared-cut load and telemetry audit

## Physical cut revalidation

The fixed topology is generated by
`experiments/pd_kv_ep/configs/generate_minimal_1p2d.py`: one ToR, six
independent NIC-to-ToR links, each 200 Gbps. This is not a parallel-link
aggregate and not a 50-Gbps-per-GPU link. FlowSim parses the same topology.

One-time route check with `FluidFlowNetwork.path()` confirmed:

```text
P0-G0 -> D0-G0 KV: 0->24 -> 24->30 -> 30->26 -> 26->8
D1-G0 -> D0-G0 EP: 16->28 -> 28->30 -> 30->26 -> 26->8
```

Both use directed link `30->26` at 200 Gbps. Corresponding D0/D1 receiver
uplinks are `30->26` through `30->29`; those are separate 200-Gbps resources.
This confirms a legal shared cut but does not by itself imply persistent
congestion.

## What FlowSim means by demand and utilization

`FlowSpec` contains flow ID, endpoints, byte count, and release time. It has
no finite unconstrained source-rate cap. Every active flow is backlogged until
its bytes finish; `_waterfill()` allocates max-min rates from link capacities.
Therefore the backend cannot produce an exact exogenous offered rate
`rho=offered_rate/capacity`, and it cannot establish `rho>1`. Those ledger
fields remain blank (`null`), not estimated from request count.

The augmented telemetry records, for each directed-link event interval:

- interval start/end and exact interval duration;
- total, KV, and EP allocated rates and utilization;
- active total/KV/EP flow counts;
- KV/EP bytes newly released onto that directed link at the interval start;
- `queue_bytes` plus its explicit alias `fluid_outstanding_bytes`.

Released-byte rate is reported only as a window-average **release-rate
proxy**, not offered load. Time-weighted utilization and fractions above 90%
/ at capacity are reconstructed from event intervals, with unobserved idle
gaps counted as zero. A mixed-link interval is one where both KV and EP active
flow counts are nonzero on the same directed receiver uplink.

## Queue limitation

In this backend, `queue_bytes` is the sum of remaining fluid bytes of active
flows using a link after the interval's service. It does not separate waiting
bytes from bytes in service. FlowSim has no packet buffer, packet queue,
ECN/PFC, drops, or DCQCN. Consequently this phase reports it as
**analytical fluid outstanding volume**, not switch queue occupancy. True
queue-episode percentiles and rho>1 episodes are unavailable; near-capacity
utilization episodes are reported separately as the defensible persistence
signal.

## Coverage and validity

Telemetry is filtered to the 12 directed NIC/ToR uplinks and capped at 500,000
rows per run. The backend now emits `telemetry_truncated_at_ns`; a queried
measurement window is marked complete only if its interval is covered before
any truncation. The D-only warm-up records the same cut telemetry as FULL so
their event-derived comparison window can be matched. No per-packet or
per-flow dump is enabled for the main capacity escalation.

## POST_PREFILL D64K1 sensitivity (2026-10-09)

The corrected, mode-matched `POST_PREFILL` run observed the same shared
directed Decode-ingress cut. In its event-derived window, D-only occupied
capacity for 16.729% of time and FULL for 18.675%; the longest >=90% interval
was 10.486 us and 9.668 ms respectively. Peak analytical fluid outstanding
volume was 261,219 B and 201,301,142 B. Same-directed-link KV/EP overlap
summed to 6.781 ms across the four Decode ingress links (0.416% of the
measured window's aggregate link-time accounting). The FULL window released
805,306,368 B KV and 6,806,306,816 B EP through the cut; their release-rate
proxies are window averages, not offered rates.

At the request level, the last KV chunk's residual drain rose from 8.063 ms to
9.636 ms (+19.51%), while arrival-to-P2D-ready increased by 6.308 ms (+1.57%).
The event ledger shows four chunk releases; each completed chunk gates the
next prefill chunk in this POST_PREFILL implementation, so service delay
accumulates at readiness. The primary LAYERWISE run instead releases KV per
transformer layer, allowing intervening layer computation to overlap network
drain; its P2D-ready time was unchanged. The modes expose different amounts
of release slack and remain separate sensitivity points.

These remain **analytical fluid-model** statistics. The 201-MB value is not a
switch queue size, and this FlowSim run does not provide packet serialization,
ECN/CNP, PFC, drops, or DCQCN evidence. The run also has no uncapped source-rate
model, so `rho` is still unavailable.
