# Round 17: incomplete agentic token IDs invalidate prefix-hash claims

**Prediction.** A tool-gap prefetch idea first needs observed lower-tier
misses and exact per-block identity. If the trace's declared token counts
and token-ID sidecars differ, the simulator cannot safely attribute
cached blocks to a future request; an apparent miss/hit rate is suspect.

**Measurement.** `theory/audit_ids.py` checks all50 committed sessions
(765 LLM calls,715 child calls). Every prompt has exactly141 fewer
`input_tok_ids` than `input_toks`, and every output sidecar is also
incomplete (20–999 missing IDs, median41). The input SHA-256 and counts
are in `theory/audit_ids.json`.

**Causal defect and repair.** The prior hash builder concatenated known
input and output IDs without accounting for the unknown141-token prompt
portion, putting output hashes before the declared prompt boundary.
Computing the whole chain upfront is safe only when positions are exact.
The builder now disables prefix hashes on a prompt-ID mismatch; normal
allocation and compute continue. A targeted future-output regression,
the full52-test P/D suite and the KV manager self-test pass.

**Outcome.** The historical29,086-block capacity estimate used the
misaligned hash chain, so its claim that all sessions fit cannot be used
as a strict no-miss proof. The trace still does not provide an observed
remote KV miss or timed CXL load. `NEED_DATA`/`SIMULATOR_UNSUPPORTED`.
No conditional tool-gap saving is promoted to a measured Serving gain.
