# Iteration 001 — cold bound and unsupported saturation

- Hypothesis: staging P2D transfers around D memory admission can remove
  network bubbles and improve Serving completion.
- Prediction: cold 1–4P cannot improve P2D-ready, because network work is
  already fully hidden; D-pool exhaustion might create a third-resource
  tradeoff, but requires correct source retention.
- Observation: prior exact-model 1P1D/4P1D ready is identical at 184.907 ms,
  last four-source flow 2.453 ms early. Existing `add_decode` raises at
  memory-full after Prefill frees its KV.
- Theory-versus-simulation: agrees in the supported cold envelope;
  saturation is unmeasured and unsupported, not a failed performance idea.
- Status: cold `NO_GO`; saturated `SIMULATOR_UNSUPPORTED/NEED_DATA`.
- Next: do not run a memory-full workload until atomic reservation/source
  retention is implemented and a finite burst gives >10% potential over
  capacity-aware FIFO/DMRS on the same fixed resources.
