- Hypothesis: later layerwise P2D flows can compete with already-running D EP
  on a shared directed 200-Gb/s link.
- Prediction: same-direction physical overlap and a D collective/token delay
  under FAIR; priority should expose whether this is merely class scheduling.
- Current evidence: prior *EP-only* synchronized control adds 0.798% ITL
  versus an isolation lower bound, so it is already `NO_GO` as its own paper
  mechanism. A later full-KV P wave was not present and remains unmeasured.
- Theory-versus-simulation: the 24-request run did produce 40,160
  same-directed-link P2D/EP interval pairs under FAIR. Every new request's
  last KV flow ended at least1.161 ms before its unchanged64.712-ms
  P2D-ready barrier. The incumbent cohort's mean TPOT was6.157552 ms in
  matched no-new-wave control and6.178858 ms with later P arrivals; old
  completion rose235.757112→236.417623 ms (0.279% removable upper bound
  if all new work were removed). EP_FIRST gives6.171083-ms old TPOT and
  236.176600-ms completion. KV_FIRST is worse and changes D batch
  composition/EP bytes, so it is a policy control rather than an
  identical-EP-byte microcomparison.
- Root cause: physical overlap exists, but P2D stays hidden by producer
  compute and the EP barrier penalty is too small at this cut. The new
  wave's FAIR→EP_FIRST mean completion change is only0.0425%.
