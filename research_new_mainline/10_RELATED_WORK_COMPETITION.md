## Novelty conclusion

`Owner-local compute after dispatch` and `partial communication/compute overlap` are already crowded and often implemented in expert pipeline systems. COMET is particularly close because it explicitly resolves token/tile data dependencies and overlaps both input communication with expert computation and computation with return communication; the generic streaming idea is therefore not a novelty claim. A plausible narrow question remains: do the current project’s AG/RS and P2P join semantics impose **avoidable, physically relevant** waits beyond the real runtime's input/output readiness, and can external directed-cut contention change a downstream Serving-barrier decision beyond COMET’s GPU task-DAG optimization? This audit does not establish that. The missing Qwen-calibrated route and profile bound is a theory-gate failure, so no algorithm should be proposed as novel yet.
